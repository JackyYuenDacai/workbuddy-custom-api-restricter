# Windows 快捷键与焦点

快捷键可以减少找控件的时间，但作用取决于当前焦点。每次先确认目标窗口和控件，使用当前 schema 支持的键名；一个动作后重新观察，不串联未经核对的按键。系统支持某个组合键，不代表当前 MCP 接受它。

## 当前 desktop_key 可用

以下按当前实现列出；后续工具 schema 如有变化，以重新发现的定义为准。

| 按键 | 常见用途 | 使用前核对 |
| --- | --- | --- |
| `TAB` / `SHIFT+TAB` | 下一个/上一个可聚焦控件 | 观察焦点位置，不能凭固定 Tab 次数猜输入框 |
| `UP` / `DOWN` / `LEFT` / `RIGHT` | 移动光标、菜单或列表选择 | 聚焦的是正文、菜单还是列表；选中不等于打开 |
| `ENTER` | 激活选中项、确认或提交 | 聊天框可能直接发送；先核对目标、内容与授权 |
| `ESC` | 关闭当前菜单/弹层或取消当前操作 | 先确认正在关闭哪个弹层；不要连按后误退出编辑 |
| `HOME` / `END` | 通常移到行首/行尾或列表边界 | 不等同于 Ctrl+Home/End 的文档首尾 |
| `PAGEUP` / `PAGEDOWN` | 在聚焦区域翻页 | 比较内容变化；不同程序也可能移动选中项 |
| `CTRL+F` | 常见查找入口 | 某些程序打开全局搜索；观察实际搜索框再输入 |
| `CTRL+L` | 支持的浏览器中聚焦地址栏 | 不是所有应用的通用导航键 |
| `CTRL+A` | 当前字段/区域全选 | 先确认选区范围，不能在未知焦点下全选后删除 |
| `BACKSPACE` / `DELETE` | 删除文字或选中对象 | 文件列表中的 Delete 可能删除文件，不当成文字编辑 |
| `CTRL+S` | 保存 | 可能覆盖文件或打开保存对话框；按真实副作用核对 |
| `CTRL+Z` / `CTRL+Y` | 撤销/重做 | 撤销栈可能包含用户的操作；不能把它当作盲目恢复手段 |

当前 `desktop_key` 需要**窗口**截图令牌，不能把 `desktop_screen_observe` 的整屏令牌用于键盘操作。瞬时壳菜单若没有可绑定窗口，就用新整屏截图点击可见菜单项，不把窗口键盘输入发给背后的应用。

## Windows 常见快捷键：了解用途，但当前工具未直接开放

这一表用于选择已有替代能力或向用户说明手动操作。当前不能把这些键名传给 `desktop_key`，也不能通过 `desktop_type_text` 输入字符串来模拟。只有未来 schema 明确支持且符合当前任务边界时才可执行。

| 系统快捷键 | 常见用途 | 当前自动化替代方式 |
| --- | --- | --- |
| Alt+Tab / Alt+Shift+Tab | 切换最近窗口 | `desktop_windows` → 选目标 → `desktop_focus`，核对实际激活窗口 |
| Alt+Esc | 按打开顺序切换窗口 | 优先按返回的窗口 ID 精确激活 |
| Alt+Space | 当前窗口的系统菜单，可恢复/移动/最小化 | 已知最小化窗口用 `desktop_focus` 恢复 |
| Win+T | 在任务栏按钮间导航 | 整屏观察任务栏分组并选择；固定图标不证明应用正在运行 |
| Win+B | 聚焦通知区域，之后可导航托盘图标 | 使用专用 `desktop_open_tray`；它内部验证隐藏图标按钮，不能假设 Win+B 本身就打开弹层 |
| Win+D | 显示/恢复桌面 | 不为找一个程序而默认隐藏所有窗口；按任务栏/托盘恢复目标 |
| Shift+F10 | 对当前选择打开上下文菜单 | 对已观察到的目标使用工具支持的右键 |
| F6 / Shift+F6 | 在某些应用的窗格间切换 | 用已支持的 Tab 或点击实际窗格，效果依应用而异 |
| Ctrl+Tab / Ctrl+Shift+Tab | 在不少应用中切换标签页 | 浏览器结构化工具或点击已观察的标签 |
| Ctrl+Home / Ctrl+End | 在不少编辑器中移到文档首尾 | 当前只有 Home/End，不能当作同义替换；使用导航或滚动 |
| Alt+F4 / Ctrl+W | 关闭窗口/标签，可能触发未保存提示 | 不是修复焦点的方法；仅在用户要求关闭且目标明确时操作可见关闭控件 |

不要以熟悉快捷键为由扩大授权或绕过 UAC、锁屏、终端权限。当前不支持的剪贴板快捷键 Ctrl+C/X/V 也不能猜测执行；粘贴可能传输用户剪贴板中的私人内容。

## 托盘图标的文字提示

通知区域和隐藏图标弹层中的图标通常在鼠标**悬停片刻**后显示 tooltip（提示文字），经常在图标上方，也可能因屏幕边缘出现在旁边或下方。打开托盘本身不保证所有图标都有提示。

先看新截图里是否已有提示，并把文字与当前悬停/高亮的图标关联。提示可以包含应用名称、账号或状态，比仅凭图标颜色判断可靠；它不是按钮，不要点击文字浮层来代替点击图标。

当前 MCP **没有单独的 hover/移动鼠标工具**；`desktop_cursor` 只读，`desktop_screen_click` 会真的点击。不要为了制造 tooltip 点击未知图标，也不要伪造 `desktop_hover`。若未来 schema 提供悬停工具，可观察定位图标 → 只移动不点击 → 短暂等待 → 新整屏观察读取提示 → 用更新的 snapshot 操作。鼠标移动、弹层关闭后旧提示不再证明新目标身份。

详细流程与限制见 [壳界面与恢复](recovery-and-shell.md)。
