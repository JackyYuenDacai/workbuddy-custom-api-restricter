# 详细排查与实现过程

本文记录当前补丁的设计依据、修改位置、验证过程和边界，不是对所有 WorkBuddy 版本行为的保证。

## 1. 原始需求

要求 WorkBuddy 只使用 `Qwen3.8-27B-EXL3-3.5bpw`，通过 `http://127.0.0.1:8317/v1` 调用，不使用 Auto 或云端模型回退，同时保留账号登录、联网搜索和其他非模型网络能力。

这里的两个问题必须分开：

- **模型推理走哪里**：需要限制模型选择、模型解析、请求目标及回退路径。
- **应用能否联网**：登录、搜索、配置获取仍然需要网络，不能整体封网。

因此没有修改系统防火墙、全局代理、hosts、登录服务地址或 TextGen 启动参数。

## 2. 为什么仅修改 models.json 不够

先检查本机自定义模型配置，确认模型条目和 API 地址正确。检查时只核对模型名称和地址，不输出 API Key。

进一步检查程序代码及诊断日志发现：

1. 桌面主程序的产品配置会重新引入 Auto 和远程模型目录。
2. CLI/ACP 的模型目录及会话模型选择并不只依赖界面显示的自定义列表。
3. 某些辅助代理具有自己的默认模型，例如原始配置中使用 `hy3`。
4. 程序有模型回退拦截器，单次主模型选择不能代表失败后的行为。
5. `CODEBUDDY_DISABLE_BUILTIN_MODELS` 只覆盖部分内置来源，不能完整屏蔽远程注入目录。

所以需要在程序模型执行路径上施加限制，而不是仅删除设置中的云端模型或依赖环境变量。

## 3. 为什么不修改 app.asar

确认当前 WorkBuddy EXE 启用了 Electron 内嵌 ASAR 完整性校验。直接修改归档里的桌面产品策略会牵涉受校验的程序资源。

最终方案选择两个由独立 Node CLI 加载的解包 JS bundle：

```text
resources/app.asar.unpacked/cli/dist/codebuddy.js
resources/app.asar.unpacked/cli/dist/codebuddy-headless.js
```

没有修改 EXE、ASAR 或完整性校验开关。`prepare` 仍读取 ASAR 元数据，用于确认原始解包文件的哈希，而不重写它。

源码中的 `restrictProduct()` 是早期产品目录策略的辅助函数，保留用于测试；**它没有被安装到桌面 ASAR 的产品策略中**。它的单元测试不能作为桌面目录已被清除或登录/搜索端到端成功的证据。早期未使用的 ASAR 重打包代码已从安装脚本移除。

## 4. 执行路径

```text
桌面 / CLI / ACP 模型选择
          ↓
模型目录过滤 + 默认/辅助模型强制选择
          ↓
模型配置与 API Base URL 强制解析
          ↓
模型 Provider 校验允许的 ID
          ↓
请求边界校验 URL / POST / JSON model
          ↓
请求变换后复查模型和地址，禁用重定向/系统代理
          ↓
127.0.0.1:8317/v1/chat/completions

登录 / 搜索 / 非推理请求 → 原有网络客户端（不改）
```

默认/辅助选择会强制采用允许模型；显式运行时切换或实际请求不符合约束则报错。两者不是同一种处理：CLI 传入 Auto 被覆盖并不表示 Auto 自己获准运行。

## 5. 修改点逐项说明

所有锚点由 `replaceOnce()` 要求恰好出现一次，在两个 bundle 中分别应用；版本变化时应停止并复查，不能仅凭方法名相似就继续安装。

| 程序入口/修改位置 | 修改目的 |
| --- | --- |
| `applyRuntimeSessionModel` | 拒绝运行时切换到不允许的模型 ID |
| ACP `currentModelId` 输出 | 将对外当前模型标记与强制模型保持一致 |
| 初始化模型快照 | 有允许模型时返回其内部 ID，没有则不虚构可用模型 |
| `computeModelsFromRaw` | 从注册的自定义模型来源过滤出唯一允许模型 |
| `computeModels` | 执行引擎的模型列表只返回允许条目 |
| `computeModel` | 默认和走该管理器的辅助代理统一选择允许模型 |
| `configureModelConfig` | 不采纳云端会话覆盖项，统一从代理管理器获取受限模型 |
| `resolveModelBaseURL` | 强制使用允许的 Base URL |
| 模型 Provider 的 `getModel` | 再次检查模型 ID，避免旁路直接取得云端 Provider |
| `requestWithConnectionRetry` | 在实际模型请求/重试前检查目标、方法和负载 |
| fallback 拦截器 `intercept` | 直接返回，不启动另一个回退模型 |

## 6. 策略函数细节

`policy.cjs` 导出的工厂函数通过 `toString()` 嵌入 bundle，生成一个冻结的 `__wbQwenOnly` 策略对象。文件开头的补丁标记用于拒绝重复注入。

### 模型校验

只允许原始模型 ID 和 `custom-local:` 加原始 ID 两种形式；发送给 OpenAI API 的 JSON 必须使用原始 ID。

`localConfig()` 保留注册条目的密钥等其他字段，但强制覆盖 ID、名称、URL、自定义协议开关，清空别名。不存在或已禁用的模型会报错，不凭空创建缺少凭据的模型，不改走云端。

其中 `local: false` 是当前 WorkBuddy 适配器使用的配置标记，目的是走自定义 OpenAI API 适配路径；它不表示允许云端推理。实际目标由 URL 和请求校验约束。

### 请求校验

第一次进入请求边界时检查：

- `modelId` 在允许列表中。
- URL 的 origin 和 pathname 为指定端点；没有 userinfo、query 或 fragment。
- HTTP 方法为 POST。
- 请求 JSON 能解析，且 `model` 为允许的原始 ID。

随后设置 `maxRedirects = 0` 和 `proxy = false`，只影响模型请求。

在 Axios 请求变换链末尾再附加检查：负载模型和最终 URL 必须仍符合策略，并重新固定重定向与代理选项。这样可以检测本路径中前序变换/拦截器造成的模型或 URL 改动。它不是防恶意修改整个运行时、替换网络适配器或其他未知请求实现的安全沙箱。

### 回退处理

禁用的是已识别的模型回退拦截器。同一个允许端点的连接重试不等于云端模型回退；允许目标不可用时不能因此选另一个模型。

## 7. 安装文件保护

准备和安装分开进行，避免边分析边覆盖程序。

1. 读取并验证原始文件。
2. 生成两个补丁文件并语法检查。
3. 写本地 manifest，记录 before/after SHA256 和受保护归档哈希。
4. install 再核对文件未变更，保存原始 JS 和 manifest。
5. 复制补丁并核对安装哈希；复制阶段出错时尝试还原。
6. restore 只接受该次补丁或该次原始文件，不覆盖后来更新的程序。

因此必须成套保存同一轮的 manifest、staged、backup。哈希主要用于防误覆盖和确认内容，不代表补丁经过 WorkBuddy 官方签名或认证。

## 8. 实际验证记录

### 启动和登录

检查 WorkBuddy 进程与启动日志，确认安装后冷启动完成，桌面启动到可交互阶段，已有登录会话仍可用。没有通过关闭网络或重写登录信息实现限制。

期间一次在受限终端内运行 CLI 出现配置服务联网 `EACCES`；换到允许相应网络的执行环境后 CLI 正常。该错误来自执行环境的网络限制，不能据此判定补丁阻断登录。

### 模型目录

用实际安装的 CLI 执行 `--help`，其 supported models 仅包含：

```text
custom-local:Qwen3.8-27B-EXL3-3.5bpw
```

### 真实推理

通过 CLI 发送固定短提示，关闭工具和会话持久化。结果如下：

| CLI 选择参数 | 实际响应模型 | 助手输出 |
| --- | --- | --- |
| 指定 Qwen 内部 ID | Qwen3.8-27B-EXL3-3.5bpw | `LOCAL_QWEN_OK` |
| `auto` | Qwen3.8-27B-EXL3-3.5bpw | `LOCAL_QWEN_OK` |
| `gpt-5.5` | Qwen3.8-27B-EXL3-3.5bpw | `LOCAL_QWEN_OK` |

该结果结合已安装请求守卫和哈希检查，支持当前 CLI 路径受限的结论；不是所有网络流量的抓包审计，也不证明代理服务端不存在独立路由行为。

### 联网搜索

仅启用并允许 WebSearch，提示搜索公开的 Python 官方文档：

- 响应模型为指定 Qwen。
- 输出事件包含 `function_call`，工具名称 `WebSearch`。
- 对应 `function_call_result.status` 为 `completed`。
- 工具结果包含 `docs.python.org`，未检测到认证/权限错误提示。
- 最终会话 subtype 为 `success`，`is_error=false`。

最初输出解析器只识别常见 `tool_use` 等格式，未识别到调用；随后依据实际事件字段补充 `function_call` / `function_call_result` 解析，再确认真实搜索结果。没有把“模型声称搜索过”作为工具成功证据。

### 自动测试

六项独立策略测试加四项需要本机安装的测试：

1. 原始和内部前缀模型 ID 的允许/拒绝。
2. 模型目录、选择和地址覆盖。
3. 允许流式/非流式请求。
4. 拒绝错误模型、端点、方法和 JSON。
5. 拒绝请求变换后的模型/地址改动。
6. 未安装的产品策略辅助函数保留 auth/search 定义。
7. 两份生成 bundle 的语法和关键补丁锚点。
8. ASAR 哈希未变。
9. 安装文件与暂存文件哈希一致。
10. 从校验过的原始备份可重建相同补丁。

## 9. 仓库整理与发布边界

为便于他人安装，将原有机器绝对路径提取到 `paths.cjs` / `paths.local.json`，提供无密钥的示例配置。没有因此修改已注入的策略；通过原始备份重建后的哈希仍应与已安装 bundle 一致。

仓库忽略完整 WorkBuddy JS、生成 manifest、路径私有配置、模型设置、日志和备份。Git 只管理自己编写的补丁、测试和文档，不把 WorkBuddy 程序或认证材料发布出去。

## 10. 已知边界

- 桌面主程序的独立 Auto 缓存未修改，界面显示可能与执行引擎不同。
- 尚未逐一实测全部辅助代理、插件或未来新增的请求路径。
- 未做退出账号后重新登录的完整流程测试，只确认现有登录仍可用。
- 允许联网搜索不意味着搜索查询离开本机受到禁止；本项目不是零出站隐私方案。
- 应用更新可能覆盖补丁，需要重新校验和按版本适配。
- 8317 等代理内部的模型别名、路由和回退不受该补丁控制。
- 若目标 API 设为远程服务，“指定 API”不再等同于“本机模型”。

遇到未知路径或版本差异时，应保持这些边界清晰，不应把当前测试结果描述成对所有未来行为的绝对保证。
