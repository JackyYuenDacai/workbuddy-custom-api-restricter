# 壳界面、焦点与失败恢复

仅在壳 UI、弹层或首次失败时读取；不要为了读指南而让已取得的截图令牌过期。

## 焦点与瞬时弹层

VS Code 的 “Work in” 选择器等瞬时弹层可改变位置或抢占焦点。点击选项没有预期变化时，停止后续输入，用 `desktop_cursor` 看真实指针和前台；前台不符合目标时再用 `desktop_windows` 检查窗口、所有者和弹窗关系。诊断位置不能成为点击坐标。

- `desktop_focus` 可恢复最小化窗口；目标有可见活动弹窗时激活弹窗，必须使用返回的 `activated_window_id` 重新观察，而非继续操作原窗口。
- `focused=false` 表示 Windows 拒绝键盘焦点。整屏观察后点击可见目标置前，再确认窗口并重新观察；仍失败让用户手动激活，不绕过权限。
- 每个新弹层是新目标。每次只点击一个可见标签，再观察；只有新图明确显示目标输入框已聚焦才输入。弹层消失时不要把旧位置当作底层控件继续点击。
- 多窗口任务依次操作；切换后重新 focus/observe，不保存多窗口令牌供以后使用。一个新观察会替换所有旧令牌。

## 任务栏与系统托盘

### 目标程序没有出现在窗口列表

`desktop_windows` 使用可见性与非空标题过滤，并有 100 个窗口的上限。列表为空或没有目标只说明本次未找到**可操作窗口**，不是进程、安装或登录状态检测。

按当前证据选择下一步，不机械重复枚举：

1. **有匹配窗口**：核对应用名、进程、标题、所有者和 `minimized`。QQ 的标题与进程名不一定相同（如 `QQ` / `QQX`）；只能依据实际返回的进程/标题关联，不能猜 exe 路径或固定 ID。最小化窗口先 `desktop_focus`，跟随 `activated_window_id`；登录/主窗口/弹窗都可能是同一应用的不同窗口。
2. **没有窗口或窗口被其他程序遮挡**：发现 `desktop_screen_observe` 与 `desktop_screen_click`，整屏观察任务栏、通知区域及其他显示器上的任务栏。选择图中已确认的目标图标；分组按钮可能先打开窗口缩略图，再观察并选择正确窗口。图标只是固定快捷方式还是运行实例尚不明确时，不根据图标存在推断运行状态。
3. **任务栏找不到目标**：先检查通知区域已经可见的图标，再用 `desktop_open_tray` 打开隐藏图标，重新整屏观察。QQ 等程序可只驻留托盘，不存在普通任务栏按钮。不要因未在主任务栏看到就跳到启动/重启。
4. **恢复已有实例**：使用新整屏 snapshot 点击已确认的应用图标。一次点击后先核对；若未恢复窗口且图标身份明确，可用新观察尝试双击，或右键后从新图中选择“打开/显示主窗口”等恢复项。不要选“退出/注销”，也不要连续单击把已打开窗口又最小化。无文字且无法可靠区分的图标不猜，改用当前 schema 支持的标识能力或请用户指出目标。
5. **壳动作后重新绑定窗口**：刷新 `desktop_windows`，按应用证据选择新窗口 ID，再 focus/observe 核对普通主界面。托盘弹层/缩略图不是应用主窗口，不能拿它们的 snapshot 输入聊天文字。

一次恢复任务中，任务栏和托盘是不同的发现途径，不把第一次空列表当作“两次操作失败”。但同一图标/焦点小步骤仍最多两次有新证据的尝试；两个途径都没有可验证目标时，报告已检查位置、可用工具和剩余不确定性，再请求用户提供最小必要帮助。不循环重启、枚举或截图。

### 托盘工具与截图

**先读图标提示（tooltip）再判断身份。** 打开托盘后，图标在鼠标悬停时通常会在上方或附近显示应用名/状态。例如提示“向日葵远程控制”对应当前悬停的向日葵图标，不能把它当作 QQ。提示只对应一个悬停目标，不是整组图标的标题；位置不是永久固定，也不是每次打开就自动出现。核对文字、高亮图标和同一张截图的空间关系，不只凭颜色或记忆猜图标。识别远程控制软件不授权打开远程会话。

当前工具没有独立 hover；`desktop_cursor` 不移动鼠标，点击也不能冒充悬停。已有提示可直接读取；提示缺失且图标不明确时，用可用的标识证据或请用户指出图标，不试点未知程序。未来工具支持悬停后，应只移动到图中目标、短暂等待、重新整屏观察再读提示。参见 [Windows 快捷键与托盘提示](windows-shortcuts.md)。

用户要求“打开系统托盘/显示隐藏图标”，或需要从托盘恢复用户指定的程序时，直接用 `desktop_open_tray`，不先要求用户移动鼠标或代点。这属于该应用任务的导航步骤；不额外推断退出托盘程序、断网、修改设置等授权。

该工具无需 snapshot，通过 Win+B 定位通知区域，确认隐藏图标按钮焦点后才 Enter；已打开时保持。它会清除旧 snapshot。`opened=true` 表示检测到可见的 Explorer 隐藏图标窗口，`performed=true` 单独不证明打开。工具不移动鼠标。

选择图标或 `opened=false` 时：
1. `desktop_screen_observe` 获取虚拟桌面图，在图内定位可见按钮/图标；不要用记忆中的任务栏位置。
2. 用该整屏 snapshot 的图片像素 `x,y` 调 `desktop_screen_click`，不换算原始显示器坐标。
3. 打开弹层、菜单或置前窗口后再次整屏观察，再点击新目标；不同弹层不复用坐标。
4. 回到有标题的应用后查 `desktop_windows` 确认 ID，回到窗口观察/输入流程。整屏 snapshot 不能用于键盘输入。

工具缺失时使用可见截图流程，必要时说明重新连接 MCP 才能刷新定义；不要默认安装或改配置。音量、网络快捷设置、通知中心并非隐藏图标弹层，按用户目标选择。

如果任务栏自动隐藏且截图没有可确认的目标，先查看当前工具是否提供安全的任务栏显现能力；不要猜屏幕边缘坐标，不用不在 schema 内的 Win 快捷键替代。`desktop_open_tray` 内部使用 Win+B 不表示 `desktop_key` 接受 WIN+B。若截图链路本身不可用，明确是观察能力受限，而不是应用不存在。

整屏观察覆盖全部显示器、任务栏和壳弹层，可能暴露无关窗口；能用窗口通道就不用整屏，也不改用多屏截图脚本收集整组图片。整屏点击不绑定 window_id，仍须确认实际可见目标、图片边界和动作授权。

### 托盘驻留应用的全局唤醒快捷键（优先于重启 exe / 盲点托盘图标）

QQ 等托盘驻留应用通常配置了全局唤醒快捷键，发送该热键即可恢复**已登录的主窗口**，是比"重新执行 exe"或"盲点托盘图标"更可靠的恢复方式：

- **重新执行 exe 不可取**：对已运行的 QQNT（`C:\Program Files (x86)\Tencent\QQNT\QQ.exe`）再次启动会弹出一个**新的登录窗**（不同 PID 的小窗口），而非恢复原已登录实例，易造成"以为没登录"的误判。
- **盲点托盘图标不可取**：整屏截图把宽虚拟桌面压到 1600px 时，每个托盘图标仅约 8px，企鹅等图标无法可靠区分，误点远控/VPN 等相邻图标风险高。
- **全局热键优先**：用户告知快捷键（如 QQ 的 `Ctrl+Alt+Z`）时，用 Python 标准库 `ctypes` 调 `user32.keybd_event` 模拟该组合键（`^`=Ctrl 0x11、`%`=Alt 0x12、字母小写英文虚拟键码，如 Z=0x5A），零依赖、不被安全策略拦截。先按序 keydown 三个键再按序 keyup。发送后刷新 `desktop_windows`，按 PID/尺寸辨认被唤出的主窗口（QQ 主窗口通常 1400+ 宽），区别于误起的登录小窗。
- 注：`Add-Type` 编译 .NET 代码、`SendKeys` 依赖 `System.Windows.Forms` 均可能被安全策略拦截；pyautogui/pynput/keyboard 默认未安装。`ctypes+keybd_event` 是当前最稳的零依赖方案。

## 登录后窗口更换与 QQ 类应用

- 登录/扫码后旧窗口消失、旧 ID 失效是重新发现窗口的信号，不是登录失败证据。先刷新列表，再按上面的任务栏/托盘路径查主界面。
- 如果后来看到二维码窗口，只能说“这个窗口显示登录界面”。尤其是尝试过再次启动时，不能据此断言原实例或所有账号都未登录；先排查是否存在已登录的主窗口或托盘实例。
- 只有已确认目标实例仍停留在登录界面，才说明需要用户完成登录。请求用户输入密码/扫码期间暂停观察，完成后刷新窗口身份。不要为了让界面出现而退出、杀进程、注销或重启；用户明确要求重启时另行按其任务范围执行。
- Windows 拒绝焦点和登录状态是两回事。`focused=false` 时按焦点恢复流程处理，不重启登录流程。任务管理器等窗口挡住目标时，观察任务栏/可见目标恢复前台，再重新核对焦点。

## 错误分流

相同小步骤最多尝试两次，每次先取得新证据并纠正原因；失败一次不等于要让用户代做，但两次失败后不循环盲点。

| 症状 | 下一步 |
| --- | --- |
| missing/stale/already used snapshot | 只重新观察所需目标一次，使用新令牌；界面不同则重新定位，不原样重放。重复过期则报告推理/往返延迟，不延长或禁用安全校验 |
| Another desktop operation is running | 不并发追加调用；等当前调用结束后观察，再决定下一步。不另启控制器竞争桌面 |
| 超时、空输出、连接中断、invalid response | **结果未知**。先只读检查是否已打开窗口、输入文字或提交；无法确认时停下。不把空输出解释为成功或“肯定未执行” |
| 前台/边界/控件变化 | 用 cursor/windows 定位当前状态，重新激活目标或其弹窗并观察，不继续输入 |
| schema 拒绝参数或缺工具 | 重新发现实际 schema，按支持能力纠正；不要反复提交无效参数。旧服务仍未更新时说明需用户保存任务后重新连接/重启 |
| 页面或面板无变化 | 根据加载指示、滚动边界、当前字段判断；只读复查后再决定。无进展时报告状态，不无限截图 |
| 无可见图像、黑屏、锁屏/RDP 断开 | 不猜坐标；说明观察限制，请用户恢复交互式桌面/图像输入链路 |
| STOP / corner pause | 立即停止输入，不自动移鼠标或删除 STOP；用户明确恢复后重新观察 |

## 指针诊断

点击和滚动主动移动系统鼠标，`pointer_moved_by_tool=true` 是正常行为，不证明用户抢鼠标。`desktop_cursor` 的两次位置不同同样不能归因于用户。托盘工具的 `pointer_moved_by_tool=false` 不代表其他 GUI 动作也不会移动指针。

`Cannot read` 表示指针读取失败；`did not reach` 表示未到目标，可能受桌面约束；`Pointer changed during input preparation` 表示准备阶段位置变化、原因未知。这些准备阶段错误不会发送点击/滚轮，但可能已移动指针；与操作发出后的超时不同。重新观察定位，不复用令牌或把所有错误称为“用户移动鼠标”。工具仅在仍命中同一原生控件时容忍最多 2 物理像素抖动，模型不得扩大容差或关闭检查。

## 停止与恢复

用户可把鼠标移至主屏 (0,0) 或整个虚拟桌面任一角落拒绝输入；也可在 MCP 源码 `computer-tools` 目录创建 `STOP` 文件，锁定启动、激活和输入，工具仍允许只读状态/观察。**这不是用户说“停止”后继续截图的许可**：收到停止请求连观察也停止。

不自行删除 STOP、不移动鼠标解除四角暂停。用户决定恢复后，确认仍要继续哪一步，重新观察当前目标；不要执行暂停前缓存的动作或令牌。
