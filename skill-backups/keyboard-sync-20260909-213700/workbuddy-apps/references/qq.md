# QQ / QQNT — Windows

QQ 经典版与新版 QQNT 的全局热键、搜索和发送键可以不同，还可能被微信、截图工具或输入法占用。不能把下面的经典默认候选当作已验证的本机设置。第一次需要某项热键时，在 QQ 设置的“快捷键/热键”与聊天输入框“发送”旁的选项中核对，并记录当前会话有效的绑定；不要改用户的发送习惯。

## 常用入口和按键

| 目标 | 按键/入口 | 适用性与结果核对 |
| --- | --- | --- |
| 恢复现有 QQ | 主技能的窗口 ID、任务栏、系统托盘流程 | 窗口列表缺失不等于退出；先查隐藏图标，不直接启动第二实例 |
| 提取/打开消息 | `Ctrl+Alt+Z` | 经典版常见默认，可更改/禁用；可能跳到未读联系人，不保证目标聊天 |
| 截图 | `Ctrl+Alt+A` | 常见可配置全局热键；可能打开 QQ 或别的软件截图层，不能作为“查 QQ 在不在”的探测 |
| 搜索联系人/群 | 主窗口搜索框；仅在当前版本明确显示时用其搜索快捷键 | 不假定 Ctrl+F 一定是联系人搜索；确认搜索范围再输入姓名/号码 |
| 搜索当前聊天 | 当前会话中的“聊天记录/搜索”入口 | QQNT/经典版入口和绑定不同；Ctrl+F 仅在菜单/设置确认后使用 |
| 列表选择 | `Up` / `Down` | 先确认焦点在搜索结果/联系人列表，核对选中项身份 |
| 打开所选联系人 | `Enter` | 只在已确认结果列表焦点时；聊天输入框里的同一键可能发送 |
| 字段切换 | `Tab` / `Shift+Tab` | 逐步核对控件，不用固定 Tab 次数猜输入框 |
| 关闭已知弹层 | `Esc` | 先判断是否截图层、搜索、候选窗或聊天窗口；不盲目重复 |
| 文本全选/修改 | `Ctrl+A`、方向键、Backspace | 仅在已确认的消息编辑框中；消息列表全选可能是另一操作 |
| 发送消息 | `Enter` 或 `Ctrl+Enter` | 以“发送”按钮选项的当前设置为准；执行前核对联系人、完整内容与已有发送授权 |
| 换行 | 当前发送模式对应的换行方式，常见为 `Ctrl+Enter` 或 `Enter` | 不能拿真实消息试验哪一个会发送；Shift+Enter 也不能跨版本保证 |

**特别注意**：当前 WorkBuddy 文字输入工具拒绝换行/控制字符，也不支持 Ctrl+Enter。若任务需要多行而工具不支持，使用已授权且可用的结构化能力，或说明缺少多行输入能力；不要偷偷把多行消息改成一行、分多次发送，或通过 Enter 试探。

## 恢复、搜索、撰写

1. 根据 QQ 标题/进程找到当前窗口；托盘恢复时读取已出现的 tooltip，常在图标上方，也可能在旁边。把提示文字与当前图标关联；不点击 tooltip 本身。仅当工具支持 hover 时才用悬停产生提示；不要拿未知图标点击代替悬停。
2. 激活后确认账号和目标联系人/群。昵称重名时结合 QQ 号、群名或用户提供的身份；不会因为“打开了一个聊天”就认为目标正确。
3. 从主窗口搜索定位联系人，核对结果，再打开。进入会话后确认聊天标题，随后聚焦输入框。
4. 写入草稿后核对全文。用户只要求准备/编辑时保留草稿；用户已明确要求向该联系人发送这些内容时，不重复索取同一授权，核对当前发送键后执行一次。
5. 查看消息气泡及发送状态；超时或界面无反馈时先核对是否已经发送，不重发来验证。登录、验证码或密码由用户处理。

## 来源与置信度

QQ 没有在本次核验中取得覆盖经典版和 QQNT 的统一官方键位表，也没有读取用户聊天内容来测试。`Ctrl+Alt+Z` 与 `Ctrl+Alt+A` 仅作为经典常见绑定候选；本机设置、菜单提示及发送方式选项是最终依据。不要编造未经确认的“快速打开联系人”组合键。
